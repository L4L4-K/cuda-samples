## Patterns

- Query devices and topology before enabling features.
- Enable peer access before direct device-to-device access.
- Partition input by device and combine results on host or one device.
- Use IPC handles for memory or events shared across processes.

## Synchronization Risks

- Device A may finish later than device B.
- Peer memory visibility needs correct API ordering.
- IPC resources must outlive imported use.
- External APIs may add their own fence or semaphore requirements.

## Reading Checklist

- Identify which side owns each allocation: host, device, managed, pinned, mapped, or external.
- Find the first transfer or mapping that makes data visible to the GPU.
- Find the kernel launch or library call that performs device work.
- Find the synchronization point that makes results safe to read on the host.
- Ask whether the sample is teaching correctness, interoperability, or performance.
