## What To Look For

- `dim3 grid` and `dim3 block` decide how much parallel work is exposed.
- `blockIdx`, `blockDim`, and `threadIdx` map each thread to data.
- A kernel usually guards `if (idx < n)` because the launch geometry is rounded up.
- Host code validates results after an explicit or implicit synchronization.

## Common Sample Patterns

- Introductory samples use one kernel and one result copy to show the host-device boundary.
- Graphics and external-memory samples launch kernels that fill buffers consumed by another API.
- Library samples may hide kernels behind cuBLAS, cuFFT, cuSolver, NPP, CUB, or nvJPEG calls.
- Performance samples compare launch geometry, occupancy, memory coalescing, and overlap.

## Reading Checklist

- Identify which side owns each allocation: host, device, managed, pinned, mapped, or external.
- Find the first transfer or mapping that makes data visible to the GPU.
- Find the kernel launch or library call that performs device work.
- Find the synchronization point that makes results safe to read on the host.
- Ask whether the sample is teaching correctness, interoperability, or performance.
